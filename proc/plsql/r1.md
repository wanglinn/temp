## 重要说明

### 1. Token 声明
新增的三个 token `SQL_EXECUTE2`、`PLSQL_BODY`、`SQL_END_EXEC` 需要在 **bison 语法文件的 declarations 部分**（通常是 `preproc.y` 或 `ecpg.header`，在 `ecpg.trailer` 之前）加入：

```yacc
%token SQL_EXECUTE2
%token PLSQL_BODY
%token SQL_END_EXEC
```

### 2. 全局变量可见性
`pgc.l` 中新增的 `enter_plsql_mode` 变量需要在 **共享头文件**（如 `preproc_extern.h` 或 `preproc.h`）中增加 extern 声明，以便 bison 生成的 parser 代码能访问到：

```c
extern bool enter_plsql_mode;
```

## 修改逻辑说明

### 1. `parser.c` — 入口识别
复用已有的 `filtered_base_yylex` **lookahead filter** 架构。当当前 token 是 `EXECUTE` 且 lookahead 为 `BEGIN_P` 或 `DECLARE` 时，将其替换为 `SQL_EXECUTE2`。这样：
- `EXECUTE IMMEDIATE` → 不变，走 `ECPGExecuteImmediateStmt`
- `EXECUTE prepared_name` → 不变，走标准 `ExecuteStmt`
- `EXECUTE BEGIN ...` / `EXECUTE DECLARE ...` → 变为 `SQL_EXECUTE2`，走 `ECPGPlsqlBlock`

### 2. `pgc.l` — 原始文本捕获
- 新增 exclusive 状态 `<xplsql>`，在此状态下用 `.|\n` **逐字符收集**所有内容（包括 `;`、换行、注释等），完全绕过现有 SQL 词法规则。
- 当 `<xplsql>` 匹配到 `END-EXEC` 时，通过 `yyless(0)` 将其**完整放回输入流**，切回 `<SQL>` 状态，并返回 `PLSQL_BODY`（内容为收集到的原始文本）。
- 下一次 `yylex()` 调用时，`<SQL>` 状态会匹配到 `end-exec` 规则，返回 `SQL_END_EXEC`。

### 3. `ecpg.trailer` — 语法框架
- `ECPGPlsqlBlock` 以 `SQL_EXECUTE2` 开头，消费 `plsql_header`（`BEGIN` 或 `DECLARE`）后，设置 `enter_plsql_mode = true` 通知词法层进入捕获模式。
- 随后接收 `PLSQL_BODY` 和 `SQL_END_EXEC ';'`，完成整个块的识别。
- Action 中将块内容直接透传输出到生成的 C 源码中。
